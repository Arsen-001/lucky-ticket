# docs-drift

Detect drift between `DOCS/DOCS.md` (the product source of truth) and the actual implementation.

## When to use

- The user just changed business logic — engine cycle rules, stake durations, referral percentages, VIP leveling, market pricing, claim flow, anything in DOCS Sections 5–19
- Before opening a PR that touches any of those areas
- The user asks "are the docs accurate?" / "did I forget to update DOCS?"
- Reviewing a feature for production readiness

## What to check

Walk through each DOCS section and verify the corresponding code matches. Focus on rules that are easy to drift on:

| DOCS section               | Spot-check                                                                                                        |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 5 Activity Points decay    | Is decay actually applied somewhere? Inactivity penalty matches docs?                                             |
| 6 Lucky Coin uses          | Does the Market sell the items DOCS lists (engines, boosts, statuses)?                                            |
| 7.4 VIP pricing            | First unlock costs more than upgrades. Both LC + XTR accepted. Endless levels. Permanent (no decay/expiry)        |
| 8.2 Ticket Details         | Locked vs unlocked rendering matches                                                                              |
| 8.5 Engine unlocking       | Requirement types in code match DOCS list (lower-tier claims, friend invites, tournaments, daily activity, tasks) |
| 9.5 Claim-gates-production | Engine pauses after each cycle until claimed. Implementation must enforce this — not run a continuous timer       |
| 9.6 Instant Claim          | Targets a specific engine; combinable with Speed Boost + Capacity Upgrade; cost in XTR per tier                   |
| 10.3 Stacking              | Speed × Capacity multiplies (a 2× speed + 2× capacity = 4× base)                                                  |
| 11 Tournaments             | Random selection at start time; more tickets = higher probability                                                 |
| 12.4 All-Tasks bonus       | Auto-awarded when last task in category completes                                                                 |
| 14 Market                  | Capacity Upgrades NOT here — Shop only (Section 19.2)                                                             |
| 15 Wallet                  | USD↔LC, TON↔LC pairs both directions; min withdrawal + commission                                                 |
| 17.2 Referral              | 10% regular, 20% Telegram Premium; tickets only, no LC commission                                                 |
| 18 Stakes                  | Exactly 3 hours; consecutive stakes blocked until claim; cancel returns LC, no rewards                            |
| 19.1 Stars earning         | Stakes (random draw), tasks (chance), friend invites (guaranteed at milestones)                                   |

## Steps

1. Read `DOCS/DOCS.md`
2. Identify what business logic the recent changes touched (`git diff` on `main..HEAD` if needed)
3. For each touched section, locate the implementation files (use Grep on key terms — `engine`, `stake`, `vipLevel`, `referralPercentage`, `instantClaim`, etc.)
4. Confirm:
   - The rules described in DOCS are enforced in code
   - Any new feature in code that isn't in DOCS is added to DOCS
   - Constants like `referralPercentage`, durations, prices match between code and DOCS
5. Produce a punch list:
   - **DOCS says, code doesn't** — needs implementation OR doc fix
   - **Code does, DOCS doesn't** — needs documentation update
   - **Conflicting numbers** — pick a source of truth (usually DOCS, but ask the user)

## Don'ts

- Don't auto-edit `DOCS.md` without confirming with the user — it's a product doc, not an autogenerated artifact
- Don't treat exact prices as drift unless the user signals they care; DOCS notes "exact LC and Star prices per level are defined by the product team and may be updated independently of this document"
- Don't conflate UI copy with business rules — wording differences in labels are not drift
- Don't grep for the literal word in DOCS — use domain terms (e.g., "Telegram Premium" → search `telegramPremium`, `Premium`, `referralPercentage`)
